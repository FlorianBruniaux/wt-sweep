**KWT : référence utile pour l'identité et les vues à fraîcheur explicite.**

- K1. Registre JSON central, indexé par chemin, avec dépôt, branche, hash, dates, génération, jeton de création et provenance distante non revue. Les écritures rechargent le registre sous `flock`, puis utilisent fichier temporaire, `Sync` et renommage. Sources : [kwt/internal/registry/registry.go:23](https://github.com/kenn-io/kwt/blob/fccb0f5aac82f21e3a2d379418e12ffb8a11dbe6/internal/registry/registry.go#L23), `:141`, `:195`. Ce registre suit l'état géré par KWT; il ne décrit pas toute la machine.

- K2. Une génération aléatoire de 16 octets, encodée sur 32 caractères hexadécimaux, est placée dans le gitdir du worktree. Elle reste indépendante des changements ordinaires du répertoire et distingue la réutilisation d'un chemin après retrait de son administration. Sources : [kwt/internal/git/git_worktree.go:1801](https://github.com/kenn-io/kwt/blob/fccb0f5aac82f21e3a2d379418e12ffb8a11dbe6/internal/git/git_worktree.go#L1801), `:1809`, `:1818`.

- K3. Attention au collecteur : `ListWorktrees()` prend un verrou puis appelle `WorktreeGeneration()`, qui crée ou remplace ce marqueur lorsque sa lecture échoue. La liste peut donc écrire dans le dépôt. `InspectWorktrees()` distingue les générations manquantes sans les initialiser, mais prend aussi le verrou KWT. Sources : [kwt/internal/git/git_worktree.go:254](https://github.com/kenn-io/kwt/blob/fccb0f5aac82f21e3a2d379418e12ffb8a11dbe6/internal/git/git_worktree.go#L254), `:295`, `:1804`. Ne pas appeler `kwt list` comme collecteur read-only de Sweep.

- K4. La suppression demande génération, branche et HEAD attendus, compare le registre, coordonne la session et vérifie les processus dont le cwd se trouve sous le worktree. `--force` permet de sauter ce dernier contrôle. **Git Worktree Runner : intégration shell/agents utile, nettoyage incompatible avec le MVP.**

- R1. GTR utilise le registre Git du dépôt courant, y compris les worktrees créés ailleurs et les chemins imbriqués. Pas de génération ou registre global de provenance dans ce parcours. Le parseur préfère `git worktree list --porcelain -z`, puis expose des champs échappés. - R2. Limite du parseur : la commande productrice est relancée dans une substitution de processus après le test initial; son statut n'est pas propagé explicitement. Le fallback sans `-z` réintroduit les ambiguïtés de découpage par ligne. Source : [git-worktree-runner/lib/core.sh:286](https://github.com/coderabbitai/git-worktree-runner/blob/d576398fc0642dc91cc248f63635e4dea283d416/lib/core.sh#L286). Sweep doit continuer à vérifier statut, terminaison et intégralité d'un seul résultat borné.

- R3. Le workflow new prépare la branche, peut fetch, copie des fichiers, lance postCreate et peut ouvrir éditeur/agent. En mode porcelain, les données de succès sont publiées après les hooks; un hook échoué peut donc laisser un worktree créé sans enregistrement de succès. Sources : [git-worktree-runner/lib/commands/create.sh:239](https://github.com/coderabbitai/git-worktree-runner/blob/d576398fc0642dc91cc248f63635e4dea283d416/lib/commands/create.sh#L239), `:262`, `:282`; [git-worktree-runner/docs/agent-usage.md:36](https://github.com/coderabbitai/git-worktree-runner/blob/d576398fc0642dc91cc248f63635e4dea283d416/docs/agent-usage.md#L36).

- R4. Le mode création machine produit chemin, branche et statut des hooks sur stdout; progression et sortie des hooks sont séparées. `go` imprime le chemin, `run` transmet un tableau d'arguments sans réinterpréter la commande. Sources : [git-worktree-runner/lib/commands/create.sh:90](https://github.com/coderabbitai/git-worktree-runner/blob/d576398fc0642dc91cc248f63635e4dea283d416/lib/commands/create.sh#L90); [git-worktree-runner/lib/commands/go.sh:20](https://github.com/coderabbitai/git-worktree-runner/blob/d576398fc0642dc91cc248f63635e4dea283d416/lib/commands/go.sh#L20); [git-worktree-runner/lib/commands/run.sh:75](https://github.com/coderabbitai/git-worktree-runner/blob/d576398fc0642dc91cc248f63635e4dea283d416/lib/commands/run.sh#L75). Les hooks Git config sont acceptés directement; les hooks approuvés sont exécutés par `eval` dans un sous-shell. Sources : [git-worktree-runner/lib/hooks.sh:19](https://github.com/coderabbitai/git-worktree-runner/blob/d576398fc0642dc91cc248f63635e4dea283d416/lib/hooks.sh#L19), `:70`, `:183`, `:280`. Pour D1, aucun import natif `.worktree.json` n'a été trouvé dans les sources produit recherchées de ces trois projets. Ce format doit être vérifié dans son producteur réel avant de fixer l'adaptateur. Éviter de concevoir un registre universel depuis les seuls noms de champs.
La génération KWT peut être lue comme donnée externe; Sweep ne doit pas la créer dans une administration Git. Un identifiant privé Sweep serait un identifiant d'observation, sans promesse d'identité durable à travers suppression/recréation ou restauration.
Le stockage privé d'un import doit garder son fichier source, digest, producteur déclaré, version si présente, date d'observation et erreurs de rattachement. Ces champs proposés ne sont pas une attestation de confiance du producteur.
Le rendu HTML peut montrer source, fraîcheur, couverture et contradictions à côté des conclusions existantes. Il reste une projection du rapport validé; il ne recalcule pas une éligibilité depuis âge, nom de branche, expiration ou état de session.
Créer, switcher avec hooks, lancer un agent et archiver ajouteraient un exécuteur et une politique d'autorisation. Les trois bases ne justifient pas ce changement de périmètre pour Sweep; commencer par un besoin utilisateur démontré et une spécification séparée.
La recherche de commandes `archive` n'en a trouvé aucune dans les sources produit ciblées. Ne pas renommer un remove en archive : une archive Sweep exigerait des garanties explicites de conservation et de restauration indépendante.
Les fonctionnalités fleet/SSH de KWT ont été repérées, mais leurs transports et garanties multi-hôtes ne sont pas audités ici. Aucun de ces constats ne certifie la couverture d'une machine, un runtime installé, l'absence d'utilisateur actif ou une restauration possible.
